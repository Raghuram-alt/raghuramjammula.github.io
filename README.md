# transcribe

An editorial YouTube transcript reader with a cream-and-rust interface, original sample reading room, summaries, shareable links, and TXT/PDF downloads.

## Run

Requires Node.js 22 or later.

```sh
npm ci
npm start
```

Open http://localhost:3000. `PORT` can override the port. `npm run dev` enables server reloads. Run `npm test` for the API and data-boundary checks.

## How it works

- Public YouTube URLs are normalized to video IDs. `youtube-transcript-plus` retrieves available captions and metadata. This is caption extraction, not speech-to-text for videos without captions.
- Completed videos of up to 90 minutes are accepted. Live, unavailable, captionless, and longer videos receive explanatory errors. YouTube may block or rate-limit requests from hosted environments.
- Summaries are extractive: up to three representative passages from the transcript, not generated claims.
- Transcripts are persisted atomically in `.data/` (override with `TRANSCRIBE_DATA_DIR`). Keep this directory on persistent storage to retain permalinks. Anyone with a link can read its transcript. Recent history is also stored in the user's browser.
- The reading room contains six clearly labeled, original editorial samples. They are not attributed to real speakers or YouTube videos.
- PDFs are generated by PDFKit with embedded local fonts. The browser provides TXT downloads and copy actions. Clipboard access requires HTTPS or localhost.

## API

```sh
curl -X POST http://localhost:3000/api/transcribe \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://www.youtube.com/watch?v=arj7oStGLkU"}'
```

The response contains `id`, `title`, `creator`, `duration` (seconds), `summary`, `segments` (text and offset in seconds), and a relative `permalink`.

- `GET /api/transcripts/:id` retrieves a saved transcript.
- `GET /api/transcripts/:id/pdf` downloads its PDF.
- `GET /api/health` checks readiness.

The server limits transcription to three simultaneous requests and PDF generation to two. PDF input is limited to 300,000 characters; TXT remains available for larger transcripts. This is a lightweight single-instance app without authentication or billing; add durable managed storage and deployment-appropriate abuse controls before opening a high-traffic public service. GitHub Pages can only serve the static interface; a Node server is required for new transcriptions, persisted links, and PDF generation.
